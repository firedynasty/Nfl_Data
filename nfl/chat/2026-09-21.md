FILES TOUCHED
-------------
streamlit_scoreboard.py -- all changes below, in the order they landed.


1. QB EPA/dropback cold-start blend was overweighting thin prior seasons.

Found by inspecting Malik Willis on the in-app QB chart: showed +0.35
EPA/dropback when his real 2026 current-season play was -0.08 (matching an
outside source). Root cause: cached_qb_epa_asof() shrunk a QB's prior-season
average toward the league mean by a flat QB_SHRINK (0.7), regardless of how
many dropbacks that average was built on. Willis's 2025 Packers season was
only 38 garbage-time dropbacks at an unsustainable +0.74 EPA/db -- the flat
shrink kept that at +0.52, and even with 59 real 2026 dropbacks, the
cold-start weight (n/(n+150)) only gave the current season 28% of the blend.

Fix: the prior average is now ALSO shrunk by its own sample size (same
150-pseudo-dropback scale as the current-season weight) before QB_SHRINK is
applied. Willis's blend dropped to +0.06 (close to his real -0.08); QBs with
full prior-season samples (Allen, Mahomes, C.Williams) were unaffected.
Side effect: fixed the whole chart's x-axis, which had been stretched from
-0.4 to +0.8 to fit Willis's outlier point, compressing everyone else.

Also: the try/except around the CURRENT season's pbp load used to silently
swallow failures and return an empty frame, indistinguishable from "no QB
has played yet." Now surfaces via st.warning() so a real fetch failure
doesn't masquerade as an empty chart.


2. QB chart week selector was silently reusing leakage-shifted data.

The QB chart's week context used to piggyback on the main "Week" selectbox
(the one that controls which GAMES are listed), but cached_qb_epa_asof()
stores each week's cumulative stat as of BEFORE that week (shifted by one,
for no-leakage predictions). Picking "Week 3" therefore silently showed
"through week 2" data -- looked broken.

Fix: qb_chart_frame()/render_qb_chart() now take an explicit `through_week`
(plain-English, inclusive) and do the +1 shift internally. Added a
dedicated "QB chart: through week" selectbox (Current + each week number),
decoupled from the games-list Week selector. "Current" resolves via the new
latest_completed_week() helper (max week with a final score). Predictions
tab's own QB chart call now explicitly passes week-1, matching the model's
own no-leakage info set (previously accidental, now intentional).


3. Added an SRS column to every game's box-score table.

stats_table() now takes srs_by_team and shows each team's SRS rating
as-of BEFORE that game's week (no leakage -- same number the Predictions
tab would have shown ahead of kickoff), as the leftmost stat column.
Always computed now (srs_ratings = cached_srs_ratings(season) moved out
from under the show_preds toggle), since the box-score card wants it
unconditionally.


4. CSV export ("Download this view") ignored the "Attach prediction row to
   games" toggle entirely.

export_df was built purely from game_stats, with no reference to show_preds
-- toggling the checkbox changed the on-screen cards but never the
download. Fixed:
  - `srs` column: always included now (mirrors box-score card change above).
  - When show_preds is on: model_line, market_line, edge, win_prob,
    model_favors_team, qb, qb_epa_db, qb_catch_pct are merged in from
    pred_by_id / cached_qb_epa_asof, per ROW'S team (not home-positive).

model_line / market_line use standard sportsbook notation per row (favorite
negative, underdog positive -- e.g. market_line=-5.5 for the favorite,
+5.5 for the dog), matching what you'd see typed into DraftKings, same
convention line_string() already used on-screen. edge intentionally does
NOT follow that same flip: it's a value signal (positive = model likes
THIS row's team more than the market does), not a spread, so
edge != model_line - market_line by design -- flipping it the same way
would invert its meaning on every favorite's row.


5. Inline "crystal ball" prediction-row text was computing edge but never showing it.

render loop in main() (Week/Team view's per-game card) built model_line and
market_line via line_string() but dropped p["edge"] entirely. Added an
edge_line using the same line_string() "TEAM -X.X" notation, inserted
between market and pred in the card text:

  SRS {away} {away_srs} @ {home} {home_srs} - model {model_line} -
  market {market_line} - edge {edge_line} - pred {pred_winner} {win_pct}%
